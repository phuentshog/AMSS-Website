# Apps Script identity visibility test

This isolated project checks whether an owner-executed, domain-restricted Apps
Script web app can read the signed-in user's identity. It does not read the AMSS
roster, accept browser-supplied identity, or return/log an email.

The endpoint returns only these fields:

- `identityAvailable`
- `schoolDomain`
- `testStatus`

## Create the temporary Apps Script project

1. Sign into the official `@education.gov.bt` Google account that will own and
   deploy this test.
2. Open [script.google.com](https://script.google.com/) and create a new
   standalone project named `AMSS Identity Visibility Test`.
3. Replace the project's `Code.gs` contents with the `Code.gs` file in this
   folder.
4. In Apps Script project settings, turn on **Show "appsscript.json" manifest
   file in editor**. Open the manifest and replace its contents with the
   `appsscript.json` file in this folder.
5. Save the project. The manifest requests only the `userinfo.email` scope
   needed by `Session.getActiveUser().getEmail()` and declares owner execution
   plus domain-only access.

## Deploy manually

1. Select **Deploy → New deployment**.
2. Choose **Web app** as the deployment type.
3. Set **Execute as** to **Me** (the deploying account).
4. Set **Who has access** to **Anyone within `education.gov.bt`** or the closest
   option restricted to that exact Google Workspace domain.
5. Do not choose **Anyone**, **Anyone with Google account**, or anonymous access.
   If the exact domain-only option is unavailable, stop without deploying.
6. Select **Deploy**. Complete the Apps Script owner authorization prompt if it
   appears, and then copy the generated `/exec` web-app URL.

These steps create the deployment in your Google account. This repository does
not contain a deployment URL, token, credential, or roster file ID.

## Run the test

1. Use a separate Chrome profile signed into only your official school Google
   account. This avoids accidentally testing whichever account is active in a
   multi-account browser session.
2. Open the copied `/exec` URL directly in that profile. If Google asks you to
   sign in, select your official school account. Do not add query parameters.
3. Read the JSON response in the browser. A successful result is:

   ```json
   {
     "identityAvailable": true,
     "schoolDomain": true,
     "testStatus": "IDENTITY_AVAILABLE"
   }
   ```

   No email address is included in the page or generated by this script in its
   own logs.

## Other expected results

- If Google does not make the active email available, or the call throws, the
  result is `identityAvailable: false`, `schoolDomain: false`, and
  `testStatus: "IDENTITY_UNAVAILABLE"`.
- If an identity is available but is outside the school domain, the result is
  `identityAvailable: true`, `schoolDomain: false`, and
  `testStatus: "OUTSIDE_SCHOOL_DOMAIN"`.

## What this test proves

A successful result shows that this deployed script, under these exact account,
Workspace, and deployment settings, received an active-user email and that its
normalized value has the school-domain suffix. It does not prove that every
teacher account behaves the same way and does not test roster matching. Run the
local portal tests separately, and test an authorized and an unregistered
account with the deployed gateway before enabling it for staff.
